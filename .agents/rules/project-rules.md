# Verdy Match Lab プロジェクト固有ルール

本ドキュメントは、グローバルルール（`GEMINI.md`）を補完し、`Verdy Match Lab` における「サッカーデータの事実性」「状態管理」「カテゴリ分離」「公開中サイトとしての安全運用」を徹底するためのプロジェクト固有ルールである。

---

## 1. サイトの目的と位置づけ

* **目的**: 単なるスコア一覧や一般的なサッカー速報サイトではなく、**東京ヴェルディおよびヴェルディファミリーの試合を、試合前・試合中・試合後の流れ（戦術的視点・観戦視点）まで含めて楽しめる個人開発のMatch Lab** である。
* **非公式ファンサイトの明記**:
  * 東京ヴェルディ株式会社、Jリーグ、WEリーグ、または各大会主催者との公式な提携・関係を示唆しない。
  * `components/ui/Footer.tsx` および `app/layout.tsx` の「非公式ファンサイト」表記を維持・保護する。
  * 架空の公式コメント、監督・選手発言、クラブ公式発表等を勝手に捏造・出力しない。

---

## 2. 試合状態（PRE / LIVE / HALF_TIME / POST）の厳格管理

試合には複数のライフサイクル状態が存在する（`types/domain.ts` の `MatchStatus = "scheduled" | "live" | "half_time" | "finished"`、および `lib/match/status.ts`, `lib/match/display.ts`）。

以下の各状態の意味と表示要件を明確に区別し、ある状態の更新時に他状態の情報を誤って上書き・削除しないこと：

| 状態 | 意味 | 表示・データ要件 |
| :--- | :--- | :--- |
| **scheduled（試合前 / PRE）** | 試合開始前 | ・見どころ・注目ポイント・キーマン<br>・軍師の三策（pending）<br>・**予想スタメン（`predictedLineups`）**<br>・出場情報・前節サマリー |
| **scheduled + actualLineups** | 公式スタメン発表後 | ・公式スタメン（`actualLineups`）を表示<br>・**予想スタメン（`predictedLineups`）を削除・上書きせず併置・保持** |
| **live（試合中 / LIVE）** | 試合進行中 | ・スコア状況・時間帯に応じた戦術軍師 β の観戦ガイド<br>・公式スタメンの確認 |
| **half_time（ハーフタイム）** | 前半終了 | ・前半終了スコア<br>・軍師の三策（前半終了時点）<br>・前半振り返りと後半修正案 |
| **finished（試合終了 / POST）** | 試合終了確定後 | ・最終公式スコア・公式記録（得点・警告・交代・スタッツ・公式記録）<br>・軍師の三策（答え合わせ: hit / partial / miss）<br>・試合総括レビュー<br>・**PRE情報（予想スタメン等）はアーカイブとして保護** |

* **禁止事項**:
  * 予想スタメンを公式スタメンとして扱わない。
  * 公式スタメン発表後も予想スタメンデータを削除・変更しない。
  * 試合終了後にPRE情報を理由なく削除しない。
  * 結果が未確定な段階でPOST総括や最終確定スコアを生成・表示しない。

---

## 3. 予想・分析（Editorial）と公式情報（Official Records）の完全分離

サイト内の情報は、**「事実（Official）」** と **「予想・分析・演出（Editorial）」** に厳密に分離する。

* **事実データ（Official Records / Factual Records）**:
  * 公式スタメン・ベンチ（`actualLineups`）
  * 公式試合結果・スコア（`homeScore`, `awayScore`）
  * 公式得点記録・アシスト（`goals`）※アシストは公式記録で明記された場合のみ
  * 警告・退場（`cards`）
  * 交代（`substitutions`）
  * 試合スタッツ（`matchStats`）
  * 公式試合記録（`officialRecord`: キックオフ時刻、入場者数、天候、気温、湿度、公式記録URL）
  * 大会・節・会場・キックオフ予定時刻
* **編集・演出データ（Editorial / Analysis / Creative）**:
  * 予想スタメン（`predictedLineups`）
  * チーム特徴・注目ポイント・キーマン（`verdyProfile`, `opponentProfile`, `focusPoints`）
  * 軍師の三策（`strategies`）
  * 戦術軍師 β のLIVEガイド・ハーフタイム分析・試合総括（`features/ai-guide/`）

* **禁止事項**:
  * 選手名、背番号、フォーメーション、得点者、公式結果などをAIの推測で「公式」として捏造・補完しない。
  * 演出や分析の都合で公式試合記録（スコア、得点者、スタッツ等）を書き換えない。

---

## 4. カテゴリ境界の維持（TOP TEAM / BELEZA / U-21）

東京ヴェルディには複数のカテゴリが存在し、それぞれデータ構造・運用方針が異なる。

| カテゴリ | 対象 | データ構造・正本 | 特徴・方針 |
| :--- | :--- | :--- | :--- |
| **TOP TEAM** | 東京ヴェルディ トップチーム | `lib/data/matches.ts`<br>Neon PostgreSQL（`DATABASE_URL`設定時）+ `lib/mock/matches.ts`（fallback）<br>日程: `lib/mock/schedule.ts` | フル機能（PRE / LIVE / HALF_TIME / POST / 三策 / 予想・公式スタメン / 公式記録 / DB連携） |
| **BELEZA** | 日テレ・東京ヴェルディベレーザ（WEリーグ） | `lib/mock/beleza.ts`（mock直接参照） | 軽量PRE / POST / 公式記録 / NEXT 5<br>※TOP用のMatch型やDB構造を無理に適用しない |
| **U-21** | 東京ヴェルディU-21（U-21 Jリーグ） | `lib/mock/u21.ts`（mock直接参照） | 公式記録・結果中心 / NEXT 5<br>※予想スタメンや戦術三策は持たない方針を維持 |

* **禁止事項**:
  * 別カテゴリの選手（TOP / BELEZA / U-21）を誤って流用・混同しない。
  * 試合履歴や日程を別カテゴリへ混ぜたりコピーしない。
  * HOMEページ上のカードやリンク先を取り違えない。
  * 「共通コンポーネント化」を理由に、3カテゴリのデータ境界や個別要件を破壊しない（共通化変更時は必ず3カテゴリすべてへの影響を確認する）。

---

## 5. 選手名・背番号・フォーメーション・試合データの正確性

* **選手情報**:
  * 選手名の漢字・表記を推測で修正しない。同姓・似た名前の選手（例: 同一姓の選手、ユース昇格選手など）を取り違えない。
  * 背番号を推測で変更しない。不明な場合は未設定とする。
  * フォーメーションをAIの勝手な判断で変更しない。
  * `captain` 表記等を勝手に追加・削除しない。
  * 公式スタメン更新時は、公式ソースと既存データの対応関係を必ず確認する。
* **試合基本情報**:
  * 試合日、キックオフ予定時刻、大会名（`fixtureMeta.competition`）、ステージ、節・回戦（`fixtureMeta.roundLabel`）、対戦相手、HOME/AWAY、会場、スコア、勝敗、得点者を事実データとして扱う。
  * 不明な値を推測で埋めない（未確定情報は "TBD" や未設定のままにする）。
  * 既存データと矛盾を発見した場合、勝手に片方を正解と決めつけて全面置換しない。

---

## 6. 過去試合データの保全と URL / Routing の保護

* **アーカイブの保護**:
  * 過去の試合ページは記録・アーカイブ資産である。
  * 新規試合追加のために、過去試合データを削除したり、過去試合のPRE/POSTを上書きしたり、match IDを使い回したりしない。
* **URL / Routing**:
  * 既存の `match ID`（例: `match-0`, `match-1`, `match-7`, `match-8`, `beleza-match-1`, `u21-match-1`）、ルート、slugは公開URLであるため、理由なく変更しない。
  * 過去試合URLへのリンク導線を壊さない。
  * 新規試合追加時は既存IDと重複しない一意なIDを使用する。

---

## 7. mockデータ・データ取得層の役割分担

* **`lib/mock/matches.ts`**: TOP TEAMの試合詳細・過去試合・検証用データのフォールバック正本。
* **`lib/mock/schedule.ts`**: TOP TEAMの公式戦スケジュール（前後最大5試合）表示用データ。
* **`lib/mock/beleza.ts`**: BELEZA専用の試合データ・公式記録・日程データ。
* **`lib/mock/u21.ts`**: U-21専用の試合データ・公式記録・日程データ。
* **`lib/data/matches.ts`**: TOP TEAMのDB取得 ＋ mockフォールバック（`isDbConfigured()`）を担うデータ取得層。
* **ルール**:
  * 新しいmockファイルを推測で増やさず、既存の構造に従う。
  * 過去に「まだ実装しない」と決められている機能・データを勝手に先行実装しない。

---

## 8. HOMEページ・UI・デザインの保護

* **HOMEページ（`app/page.tsx`）**:
  * TOP TEAMだけに偏らず、ヴェルディファミリー（TOP, U-21, BELEZA）の構成を尊重する。
  * Hero、NEXT MATCH、各カテゴリカードの導線や役割を勝手に削除・変更しない。
  * 単に情報量を増やすだけのUI変更や、コンセプトを確認しない全面リニューアルを行わない。
* **デザイン・ブランド表現**:
  * 東京ヴェルディを象徴するグリーン（`verdy-green`, `deep-green`, `pioneer-gold` 等）をアイデンティティとしつつ、**可読性と試合情報の理解しやすさ** を最優先とする。
  * 単に緑を増やしたり、グラデーションやカードを過剰に追加してAIテンプレート化しない。
  * 明示的なデザイン改善依頼がない限り、全面再設計を行わない。
* **レスポンシブ対応**:
  * 変更時はデスクトップ（PC）およびモバイル（スマホ）の両方でレイアウト崩れがないことを確認する。

---

## 9. 写真・画像・ローカル保護対象

* **`public/images/`**:
  * 既存の写真（スタジアム風景、ピッチ写真等）を明示的な指示なく削除・置換・加工しない。
  * 写真の参照先やファイル名を理由なく変更しない。
  * 画像レイアウト（`contain-split`, `cover-top`, object-position等）の意図（エンブレムやピッチのトリミング防止）を尊重する。
* **権利保護**:
  * Webから無断取得した選手顔写真、公式ロゴ、クラブエンブレム、プレス写真を追加しない。
  * ユーザー提供・ユーザー撮影素材は重要な独自資産として扱い、勝手に推測で削除・移動しない。
* **ローカル資産の保護**:
  * `.claude/launch.json`: ローカルの既存未コミット変更を維持し、勝手にreset / restore / clean / commitしない。
  * `Pictures/`: Git未追跡のローカル素材ディレクトリであり、削除・移動・clean・stageしない。

---

## 10. Database・環境変数・安全ルール

* **`DATABASE_URL`**:
  * サーバー専用（Server-only）として扱い、`NEXT_PUBLIC_` プレフィックスを付けたりクライアントバンドル・ログへ露出させない。
  * `lib/db/server.ts` の `isDbConfigured()` ガードによる DB ＋ mock fallback アーキテクチャを維持する。
* **外部AI API**: 現在未使用。明示的な指示のない新規追加や依存関係追加は行わない。

---

## 11. 実装・検証・Git運用

* **検証コマンド**:
  * Lint: `npm run lint`（`eslint`）
  * Build & 型チェック: `npm run build`（Next.js build + TypeScript check）
  * 差分確認: `git diff --check`
  * ※ 存在しないテストコマンド等を推測で実行しない。
* **Git / デプロイ運用**:
  * 既存の未コミット変更（`.claude/launch.json`等）を削除・破棄しない。
  * 作業対象外ファイル（`Pictures/`等）をstageしない。
  * 指示のない commit / push / deploy は行わない。
  * VercelやGitHubの設定を勝手に変更しない。
  * `reset` / `rebase` / `amend` / `force push` は実行しない。
